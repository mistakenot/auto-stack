# 1.2 — Lifecycle-aware retrieval

## Goal

Make rule lifecycle actually affect retrieval. Today `retrieve` (and `rule list`) ignore
`lifecycle`, so `draft` and `stale` rules surface identically to `confirmed` ones. After this:

- `retrieve` **never** surfaces `stale` rules.
- `retrieve` surfaces `draft` rules **flagged** by default; `--no-drafts` excludes them.
- Each retrieved rule carries its `lifecycle` and a `draft` boolean in the output.
- `rule list` gains a `--lifecycle` filter and shows lifecycle in both JSON and text.

This turns `draft` into a real candidate state and is the gate the consolidation step (1.4)
relies on.

## Files (module: `auto-reflect/`)

Modify:
- `internal/rules/match.go` — lifecycle filtering in `MatchRules`.
- `internal/loop/service.go` — `RetrievedRule` gains `Lifecycle` + `Draft`; `Retrieve` plumbs a `includeDrafts` arg.
- `internal/cli/retrieve.go` — `--no-drafts` flag; output/text include lifecycle + draft.
- `internal/cli/rule.go` — `rule list` `--lifecycle` filter + lifecycle in output.

Tests:
- `internal/rules/match_test.go` — extend.
- `internal/cli/cli_integration_test.go` — extend (use `runCLIAt`, `:514-551`).
- `cmd/autoreflect/e2e_loop_test.go` (or a new `e2e_lifecycle_test.go`) — black-box.

Do **not** touch `root.go`, `quickstart.go`, observation files, consolidation, or stats.

## Behaviour detail

### `MatchRules` (match.go)
Current signature: `MatchRules(rules []Rule, intent string, domainFilter []string) []Match`.
Change to: `MatchRules(rules []Rule, intent string, domainFilter []string, includeDrafts bool) []Match`.

Filtering rules, applied to BOTH the scored candidate set and the hard-injection set:
- Drop any rule with `Lifecycle == LifecycleStale` (`rules.LifecycleStale`) unconditionally.
- If `!includeDrafts`, also drop `Lifecycle == LifecycleDraft`.
- Rules with empty/legacy lifecycle: treat a non-`stale`, non-`draft` value as surfaceable
  (don't accidentally hide `confirmed` or unset). Only `stale` and (when excluded) `draft`
  are filtered.

Hard rules: a `stale` hard rule must NOT be force-injected (stale beats hard). A `draft`
hard rule follows the same `includeDrafts` rule as soft. Keep the existing scoring/order.

### `Retrieve` (service.go)
- `RetrievedRule` adds `Lifecycle string \`json:"lifecycle"\`` and `Draft bool \`json:"draft"\``
  (`Draft` = `rule.Lifecycle == LifecycleDraft`).
- `Service.Retrieve(intent string, domains []string, limit int, includeDrafts bool)` — thread
  the flag into `MatchRules`. Update the existing call site.
- The retrieval **event** payload is unchanged (still records the surfaced rule ids); only the
  returned view gains fields. Do not change `events.RetrievalItem`.

### `retrieve` CLI (retrieve.go)
- Add `--no-drafts` (default false → drafts included). Pass `includeDrafts = !noDrafts`.
- JSON: each item now includes `lifecycle` and `draft` (automatic via struct tags).
- Text (`printRetrievedText`): append lifecycle, e.g.
  `rt-… [soft] (go,cli) <use_when>  lifecycle=draft`. Keep it one line.

### `rule list` (rule.go)
- Add `--lifecycle <draft|confirmed|stale>` filter (optional; validate against
  `rules.LifecycleDraft/Confirmed/Stale`, fail-fast with remediation on a bad value).
  No filter → return all (list-returns-all convention).
- JSON item: add `"lifecycle": r.Lifecycle`. Text: append ` lifecycle=<x>`.

## Validation / edge cases

- `--lifecycle` with an invalid value → `ExitError{Code:1}` + message listing valid values.
- Stale rules never returned by `retrieve` even with a matching `--domain` hard rule.
- A `retrieve` with only stale/draft matches and `--no-drafts` returns `[]` (valid empty JSON
  array), exit 0.

## Test plan

**Unit (`match_test.go`):**
- stale rule excluded (soft and hard) regardless of `includeDrafts`.
- draft rule included when `includeDrafts=true`, excluded when `false`.
- confirmed/unset rule always included.
- draft hard rule respects `includeDrafts`; stale hard rule never injected.
- ordering/scoring unchanged for confirmed rules (existing assertions still pass).

**CLI integration (`cli_integration_test.go`):** seed a repo with one draft, one confirmed,
one stale rule (create via `rule create --lifecycle …`), then:
- `retrieve <intent>` default → includes draft + confirmed, excludes stale; items carry
  `lifecycle`/`draft`.
- `retrieve <intent> --no-drafts` → confirmed only.
- `rule list --lifecycle draft` → only the draft; bad `--lifecycle bogus` → exit 1 + stderr hint.

**E2E (`cmd/autoreflect`):** build-once binary; create the three rules, assert the same
default/`--no-drafts` behaviour on real JSON via `requireFields`.

## Acceptance criteria

- `go build ./... && go vet ./... && go test ./...` green in `auto-reflect/`.
- `retrieve` excludes stale, flags drafts, honours `--no-drafts`; output carries lifecycle+draft.
- `rule list --lifecycle` filters; invalid value fails fast with a hint.
- All pre-existing tests still pass (update call sites for the new `MatchRules`/`Retrieve` args).
