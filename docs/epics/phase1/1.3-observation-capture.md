# 1.3 — Observation capture (the Observe step)

## Goal

Restore the working-memory tier: agents record evidence-linked **observations** (situated
findings), separate from rules. Observations are a new append-only event type on the existing
event log. This is the foundational schema that 1.4 (consolidation) and 1.5 (reader API)
build on, so correctness of the payload shape matters most.

Commands (locked naming): `auto reflect observation add` and `auto reflect observation list`.

## Files (module: `auto-reflect/`)

Create:
- `internal/cli/observation.go` — `observation` parent + `add` + `list` subcommands.
- `internal/observations/model.go` — `Observation` struct, kinds, `Validate`, id minting.
- `internal/observations/model_test.go`.
- `internal/cli/observation_integration_test.go` (or extend `cli_integration_test.go`).
- `cmd/autoreflect/e2e_observation_test.go`.

Modify:
- `internal/events/model.go` — add `TypeObservation = "observation"`, an
  `ObservationPayload`, include it in `Validate`'s allowed `type` switch and the enum message.
- `internal/cli/root.go` — register `newObservationCmd(application)` (see Integration notes).

Do **not** touch retrieval/match/rule lifecycle (1.2), consolidation (1.4), or stats (1.5).
Reading observations for consolidation/stats is 1.4/1.5's job — you only provide `add` + `list`.

## Schema

`events.ObservationPayload` (canonical, on the event):
```go
type ObservationEvidence struct {
    SessionID string `json:"session_id"`
    MessageID string `json:"message_id,omitempty"`
    Quote     string `json:"quote,omitempty"`
}
type ObservationPayload struct {
    ObservationID           string                `json:"observation_id"` // ob-[0-9a-f]{8}
    Kind                    string                `json:"kind"`           // correction|pattern|gap|incident
    Subject                 string                `json:"subject"`
    Evidence                []ObservationEvidence `json:"evidence"`
    Context                 string                `json:"context,omitempty"`
    SuggestedGeneralization string                `json:"suggested_generalization,omitempty"`
    Domain                  []string              `json:"domain,omitempty"`
    Severity                string                `json:"severity"`       // normal|high
}
```
Mirror this as an `Observation` view type in `internal/observations/model.go` for list output
(add `ID`, `TS`, `SessionID` from the envelope when projecting). Keep the id pattern
`^ob-[0-9a-f]{8}$` (mint with crypto/rand, UnixNano fallback — copy `rules.NewRuleID`).

## `observation add`

Flags:
- `--kind correction|pattern|gap|incident` (required)
- `--subject <str>` (required, trimmed non-empty)
- `--evidence-session <id>` (repeatable; **≥1 required**)
- `--evidence-quote <str>` (repeatable; positionally paired with `--evidence-session` by
  index — quote[i] attaches to session[i]; extra quotes → validation error; fewer is fine)
- `--evidence-message <id>` (repeatable; same positional pairing, optional)
- `--context <str>` (optional)
- `--suggested-generalization <str>` (optional)
- `--domain <tag>` (repeatable/comma; normalized + validated like rule domains — reuse
  `rules.NormalizeDomain` is fine, or duplicate the tag regex `^[a-z0-9]+(?:-[a-z0-9]+)*$`)
- `--severity normal|high` (default `normal`)
- `--format json|text` (default json)

Behaviour: validate → mint `ob-` id → `events.AppendEvent(cwd, events.TypeObservation,
payload, events.AppendOptions{})` (session id auto-detected from env, including the new
`CLAUDE_CODE_SESSION_ID`) → print the stored observation. JSON: `{"created": true, "scope":
"repo", "observation": {…}}` (mirror `rule create`'s envelope).

Validation (structured errors via `writeValidationErrors`):
- `kind` in the enum; `severity` in {normal,high}.
- `subject` non-empty.
- evidence: ≥1 session id; each session id non-empty; quotes/messages count ≤ session count.
- domain tags: format + dedupe (reuse the rule tag rules).

## `observation list`

Flags: `--kind`, `--domain`, `--since`, `--after`, `--before`, `--unconsolidated`,
`--limit` (0 = all), `--format`. Reuse `internal/timefilter` for `--since/--after/--before`
(see how `feedback`/`stats` use it). `--unconsolidated`: in THIS slice there is no
consolidation yet, so define it as "no `consolidation` event references this observation id".
Since that event type doesn't exist yet, implement the filter as a predicate over the event
log that currently always passes (every observation is unconsolidated) but is structured so
1.4 can flip it on by checking for a referencing consolidation event. Document this clearly in
code. Newest-first order. JSON: `{"scope": "repo", "observations": [...]}`.

Read via `events.ReadAll(repo.Root)`, filter `Type == TypeObservation`, decode payload,
project to the `Observation` view, apply filters, sort desc by `ts` then id.

## Validate() change (events/model.go)

Add `TypeObservation` to the `switch e.Type` allowed cases AND to the enum error message
string. Keep `IsRuleEvent` returning false for observations (they must NOT dirty the rule
projection / `folded_through`).

## Test plan

**Unit (`observations/model_test.go`):** validation matrix — missing/invalid kind, empty
subject, zero evidence sessions, too many quotes, bad/duplicate domain tag, bad severity;
id format; happy path.

**CLI integration:** temp repo + `AUTO_SESSION_ID` set (via `runCLIAt`):
- `observation add --kind gap --subject … --evidence-session s1` → one observation event on
  disk (assert by reading the shard, like `assertLoopEventsOnDisk`), JSON envelope correct.
- failure cases: missing `--kind`, missing evidence session, bad severity → exit 1 + stderr.
- `observation list` returns newest-first; `--kind`, `--domain`, `--since`, `--limit` filter;
  `--unconsolidated` returns all (no consolidation yet).
- JSON mode: stdout strictly parseable, errors on stderr.

**E2E (`cmd/autoreflect/e2e_observation_test.go`):** build-once binary; `add` then `list`
in a temp repo; verify on-disk `observation` event has the required fields + provenance
(session id, git) via `requireFields`/shard read.

## Acceptance criteria

- `go build ./... && go vet ./... && go test ./...` green in `auto-reflect/`.
- `observation add` writes a valid `observation` event with ≥1 evidence session + provenance.
- `observation list` filters by kind/domain/time/limit and `--unconsolidated`, newest-first.
- Observations never alter the rule projection (`rule list`/`stats` unaffected; add a test
  asserting `folded_through` / rule count is unchanged after adding an observation).
