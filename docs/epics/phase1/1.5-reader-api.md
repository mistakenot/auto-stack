## Goal

Expose the loop's signal without hand-parsing sharded JSONL: a raw `events list` reader, an
unconsolidated-observation backlog count, and richer per-rule `stats`.

## Commands

### `auto reflect events list`
Raw, read-only view over the canonical event log.
Flags: `--type <t>` (repeatable; one of the known event types — validate against the
`events.Type*` set, fail-fast on unknown), `--since`, `--after`, `--before` (reuse
`internal/timefilter`), `--session <id>`, `--limit` (0 = all), `--format json|text`.
Behaviour: `events.ReadAll(repo.Root)`, filter, newest-first, project the envelope
(`id, type, ts, seq, session_id, agent`) plus a compact payload summary. JSON:
`{"scope":"repo","events":[...]}`. Keep stdout pure JSON.

### `stats` enrichment (modify `internal/cli/stats.go` + `internal/loop/service.go::Stats`)
Add, without breaking existing fields (`surfaced/selected/selection_rate/feedback_count`):
- `unconsolidated_observations` (top-level): count of observations not referenced by any
  `consolidation` event. (Until 1.4 lands the type may not exist on your base branch — gate
  on the constant existing; coordinator will confirm.)
- per-rule `rank_distribution`: map of rank → count, folded from `feedback` events'
  `rankings` (join `fb-id → rule-id` via selection events, as `Stats` already does).
- per-rule `outcome_counts`: `{success,partial,fail}` counts from `feedback` events whose
  selection surfaced that rule.

Keep `Stats` a pure fold over `events.ReadAll`; no new event types written.
