# Feedback: Task 034

## Problems faced
1. **Planned dependency-API names ≠ merged signatures.** The plan/context were written when 032/009/033 were *planned, not merged*. At execution time the real merged APIs differed in places — e.g. `Manifest.RenderVersion` is a **string** (not an int), there is no clean "fetch refs only" cache method (had to advance floats via `Realize(ref)` + `ResolveRef("FETCH_HEAD^{commit}")`), and `Realize` can return nil while the pinned object is still absent (so phase B re-verifies with `CommitPresent` before declaring success). Every subagent was told to read the real code and adapt to the merged signature — the *contract*, not the identifier, was load-bearing.
2. **`skills.yaml` `replacements` schema mismatch (T1/032 seam).** 032 types `replacements:` as an unnamed `[]yaml.Node` sequence; the design (source of truth) intends a named `var: value` map. The render engine fully supports named replacements, but a literal can't bind to a var name end-to-end through 032's current schema. Replacement-free skills render fine and the AC-designated render-unit tests pass. Filed as follow-up `auto-faf` rather than expanding T4 to rewrite a sibling task's input schema + validator mid-execution.
3. **Local-git vendored lock URLs (T3/033 seam).** A local-*git* `add` writes a bare-path lock URL the sync cache can't open (`invalid path component`). Post-add auto-sync therefore reports the outcome on stderr but never overrides `add`'s exit code (the add itself succeeded). Filed as follow-up `auto-nfx`.
4. **`opts.AutoUpdate` default subtlety.** The plan text said "set `AutoUpdate = true` by default," but the engine computes `opts.AutoUpdate || syaml.AutoUpdate`; forcing it true would override a project's `auto_update:false` and break AC-11's `--locked` > `auto_update` precedence. Left it unset and let `skills.yaml` drive floating (`init` writes `auto_update:true`).

## Reflections
- **What was tricky:** the determinism + security boundaries — the skip oracle deliberately hashes raw on-disk bytes (stamp included) so a *forged* `metadata.auto_skill` stamp changes the digest and forces a re-render (a stamp-excluding compare would have missed the forgery); and the journaled commit's byte-identity (avoid `json.RawMessage`, which the outer marshal compacts — embed typed structs and re-marshal via `skill.EncodeJSON` so live and recovery writes are byte-identical).
- **What I'd tell myself at the start:** verify the dependency packages are *merged and green* before touching anything — the context.md's "planned, not merged" caveat was the single most important thing to resolve first. They were all merged, which unblocked the whole task.
- **What I almost did but didn't:** expand T4 to fix the 032 `skills.yaml` schema so replacements work end-to-end. Held off — it's a T1-owned input schema that ripples into `add`/033, and the design-vs-merged mismatch is a cross-task coordination call for a reviewer, not a unilateral mid-execution rewrite.
