Auto-stack components are growing ad-hoc, incompatible communication paths: auto hooks fire POSTs a bespoke HookEvent to an auto-ui endpoint that doesn't exist; auto-watch traps its events in SQLite; and auto-reflect invented its own JSONL envelope. There is no shared standard for push events or two-way RPC, and the web UI has no way to know when an agent changes something it is rendering.

Define one unified communication standard — the auto bus — for streaming push events and two-way JSON-RPC over pluggable transports. Prove it with a single end-to-end use case: the web UI renders a planning doc and live-reloads it the moment a coding agent edits that file.

  • Framing: JSON-RPC 2.0 everywhere. Requests/responses = RPC; notifications = events.
  • Envelope: CloudEvents-shaped (shape only, no library dependency), strongly typed and validated.
  • Topology: a auto-shared/bus package hosted inside the auto-ui server.
  • Delivery: at-most-once, explicitly lossy — events are invalidations, not state transfer.
  • Subscription: broadcast every event to all WS clients; filtering is client-side.

The auto-ui server is the hub: the only long-lived process with a port. Everything publishes to it; subscribers fan out from it. Components never talk to each other directly — they only know the bus. The hub also enriches: it derives higher-level events (doc.changed) from raw ones (agent.tool.post) using the shared project registry.

Hooks fire from worktrees / branches at arbitrary paths, not the registered main repo. A relative path alone is ambiguous (it exists in N worktrees); an absolute path alone is unstable (machine-specific, recycled). So events carry a thin layer of workspace provenance, captured once by the producer via git:

Result: the live-reload loop is workspace-correct. An edit in worktree X reloads the UI only if it's displaying worktree X. This also forces resolving project by remote (a worktree path won't prefix-match main).

Hooks come from worktrees/branches in other locations. How do we link an event back to the feature/branch/workspace it belongs to? File events should probably carry both relative and absolute paths. An event on the wire is a JSON-RPC notification, identical inbound (publish) and outbound (broadcast). method = the dotted event type so a client's on("doc.changed", …) works directly; broadcast-everything still holds (every event reaches every client; on is just client-side interest).

{ "jsonrpc": "2.0", "method": "agent.tool.post", "params": { "specversion": "1.0", "type": "agent.tool.post", "source": "auto/hooks/claude", "id": "ev-9f3a1c20", "time": "2026-06-11T10:22:03Z", "project": "auto-stack", "session": "sess-123", "remote": "https://github.com/mistakenot/auto-stack", "branch": "feat/021-auto-bus", "worktree": "/home/vscode/wt/auto-stack-021", "commit": "803b662", "data": { "tool": "Edit", "event": "PostToolUse", "paths": [ { "rel": "docs/tasks/021-auto-bus-standard/plan.md", "abs": "/home/vscode/wt/auto-stack-021/docs/tasks/021-auto-bus-standard/plan.md" } ], "raw": { "tool_name": "Edit", "tool_input": { "file_path": "/home/vscode/wt/auto-stack-021/docs/tasks/021-auto-bus-standard/plan.md", "old_string": "…", "new_string": "…" } } } } }
  • Publish: producer POSTs this exact frame to /api/rpc (fire-and-forget). Malformed → HTTP 400 + JSON-RPC error, not broadcast; valid → 204.
  • RPC (doc.list/doc.get/ping) are normal id-bearing JSON-RPC requests over /api/ws.

Preserve-and-normalize payloads. For tool events, data carries two layers: a raw object that preserves the agent's original tool fields verbatim (no fidelity loss — each agent's tool_input schema differs), plus normalized fields (tool, event, paths[]) that copy the same values under one naming standard. Consumers code against the normalized interface; the raw layer stays available for anything tool-specific. This is the same discipline as the envelope itself — typed where we author, opaque where we carry.

For the event payloads, we should preserve all the original coding-tool fields. If we want to normalize across tools we should add new fields that copy the values but normalize to a single naming standard — so even though each agent's version of FileEdited has a different schema, they all conform to the same interface. Adopted as a two-layer payload: data.raw preserves the agent's original fields verbatim (lossless), and normalized fields (tool, event, paths[{rel,abs}]) form the shared cross-tool interface consumers code against. Reflected in the wire-format example and the ToolPost struct (Solution tab). Fits the existing typing discipline: typed/normalized where we author, opaque json.RawMessage where we carry.

Typing discipline: the envelope is strongly typed and validated (the stable contract every component compiles against); data is opaque (json.RawMessage) for ingested agent bodies and typed only where we author it (hub-derived events, RPC results).
