`auto hooks fire` (task 020) is the single point every Claude/Codex hook flows through, but the only thing it does with a payload is **best-effort POST** a small normalized `HookEvent` to auto-ui — a live, explicitly-lossy signal. If the UI is down (the common case), the event is **gone**. There is no durable record of hook activity for auto-etl to ingest, so the rich, high-frequency hook stream — *every tool call, prompt, session start/stop across every agent* — is never captured into the canonical parquet datasets that auto-search and auto-reflect build on. `PostToolUse` alone dominates the volume and carries the most signal. Two halves coupled by **a file format, never code at runtime** — consistent with the monorepo rule "the tool binaries don't depend on each other; they depend on a common data / file format." 1. **Producer** — `auto hooks fire` appends every payload **verbatim** to a daily-partitioned JSONL log (`~/.auto/hooks/raw/events-YYYY-MM-DD.jsonl`), wrapped in a thin capture envelope, **before** the existing best-effort POST. 2. **Consumer** — `auto etl run` learns a new incremental `hooks` source that reads the JSONL, normalizes a stable column set, preserves `raw_json`, and writes a monthly-partitioned `hooks` parquet dataset.
