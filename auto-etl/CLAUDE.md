# Auto-etl

IMPORTANT: this is a clean implementation of auto-etl, we can write fresh code, but you can explore the code in auto-etl to see how we do file discovery and reading.

For now this is experimental, keep it fast and simple. Use golang.

## Decision principles

- Keep as much original data as possible. Treat it as immutable. Create new fields rather than replace/transform existing ones. (Exception: security screening.)

## Spec

Takes raw Claude sessions from `~/.claude/projects` and transforms them into partitioned parquet under `~/.auto/etl/output`.

Current authoritative datasets:

- `messages`
- `sessions`

These are incremental. Past partitions are immutable; only the current time period is rewritten.

```
~/.auto/etl/output/
  messages/year=2025/week=12/messages.parquet   ← one file per ISO week
  messages/year=2025/week=13/messages.parquet
  sessions/year=2025/month=03/sessions.parquet  ← one file per month
```

Keep the schema aligned with `docs/user-journey.md` and `auto-etl/internal/model/model.go`.

`SessionRow` should include at least:

- `id`, `parent_session_id`, `host_id`, `agent`, `subagent_name`, `is_subagent`
- `workspace`, `git_remote`, `model`, `source_path`
- `first_message_at`, `last_message_at`
- `total_input_tokens`, `total_output_tokens`, `total_tokens`
- `total_bytes`, `total_output_bytes`, `total_input_bytes`
- `transcript_full`, `transcript_truncated`
- `year`, `month`, `schema_version`

`MessageRow` should include at least:

- `id`, `session_id`, `host_id`, `index`, `role`
- `content`, `content_truncated`, `timestamp`
- `tool_name`, `tool_input`, `tool_file_path`, `tool_file_start_line`, `tool_file_num_lines`, `tool_file_total_lines`
- `bash_command`
- `input_tokens`, `cache_input_tokens`, `output_tokens`
- `workspace`, `git_remote`, `git_branch`, `model`, `parent_session_id`, `is_subagent`
- `source_line_index`, `year`, `week`, `month`, `schema_version`

Store file contents from read/write/edit tools inline in `content`; use the truncated companion fields for LLM-friendly projections rather than moving the canonical session data into a third `blobs` dataset.

## Git history storage idea

- Identical files across commits store content exactly once
- `tree_entries` is just hashes — very small
- You can reconstruct any file at any commit with a single join
- If we later add blob-style storage for git reconstruction, it should layer on top of the canonical `messages` / `sessions` parquet datasets

**The full storage picture if you want complete git reconstruction:**
```
commits/
  year=2025/month=03/commits.parquet     ← commit metadata

commit_files/
  year=2025/month=03/commit_files.parquet ← diffs + change stats

tree_entries/
  year=2025/month=03/tree_entries.parquet ← full file tree per commit

blobs/
  prefix=ab/blobs.parquet ←content-addressed, no time dimension
  prefix=cd/blobs.parquet
  prefix=de/blobs.parquet
